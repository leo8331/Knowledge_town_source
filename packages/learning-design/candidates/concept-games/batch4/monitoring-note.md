# Drift observatory renderer contract

Source concepts: 1.2-lesson-4, 1.2.3-unit-1, 1.2.3-unit-2 of frozen enhanced knowledge. Root attaches full source/prerequisite evidence, exact context and hashes. All records, binary outcomes, four-row windows and the three-error response rule are explicitly synthetic exercise conditions. No production systems, retraining or actual rollback occurs. Finite observed relations do not establish a universal root cause. This simulator operates quality; it does not claim to simulate latency, cost and failure-rate monitoring in full.

UMD plugin global ConceptMonitoringGames, kinds=['drift-observatory']; init/step use the standard pure plugin protocol. Root must own teaching acknowledgement, replay, collection and context validation. Plugin result is not collection authority.

Initial data has empty opened/metrics/judgments/responses. Show goal, policy, boundary and window labels. Window rows become visible only after inspect. Inputs low/high and predictions/actual 0/1 are exercise data, not codes the user must memorize. Render actual null as “unknown / 未回流”.

- inspect {windowId}: opens record table.
- measure {windowId,values:{highPercent?,errors?}}: numeric share and error count, or explicit unknown toggle for errors. Omitted fields preserve correct existing values. Must inspect first.
- judge {comparisonId,decision}: natural language choices from config.options after both windows have valid measurements.
- respond {comparisonId,decision}: natural language actions from config.responses after a supported judgment.

Show all correct values/other judgments after wrong attempts; feedback pinpoints window/metric/comparison/response and carries sourceUnitId for knowledge rereading. Do not show config.comparisons.expected/response/reason/responseReason upfront; use judgment feedback after action. Never display internal IDs as answer instructions. May always reread source knowledge. Corrected completion is practice, not independent formal mastery.

No aggregate “all green” if a window is missing, null was guessed as zero, shares/errors are wrong, one comparison is unsupported or its response is absent. Same observations can support input shift without measured damage, changed observed relation with quality loss, or unknown quality. A hardcoded immediate retrain response never substitutes for investigation or authorized urgent fallback under the explicit exercise plan.
