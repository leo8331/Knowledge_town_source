# 拾知小镇｜参赛产品简报与新对话交接

> 用途：让项目内新对话快速理解产品，讨论OPC与游戏赛道；不是已决定的报名方案。依据用户贴出的赛道说明及本地实际产物整理，未核验赛事完整官方规则。请先核实赛事名称、时间、既有项目使用要求和提交限制，再定赛道。

## 1. 产品一句话

**拾知小镇（Knowledge Town）：把学习材料变成可以探索、操作、练习与复习的互动学习游戏。**

向学习者解释：不只是看卡片、刷题，而是在小镇里找到知识物件；部分已接入小游戏的物件通过对应的小实验或操作帮助理解概念，再进入应用与复习。

向潜在付费客户解释（待验证的服务定位）：**把你已有的一套培训或教学材料，制作成可交付的互动学习体验。**当前适合先做带人工审校的服务，不能承诺任意教材一键生成高质量完整游戏。

核心资产是“材料—有来源的知识—教学活动—游戏呈现”的可复用流程，而非每换一门课程都重新画一款大型游戏。

## 2. 面向什么问题

- 学习者：材料枯燥、概念难理解、只会背定义、刷题与知识脱节、复习缺乏动力。这些是产品假设，不是已经调研证实的需求结论。
- 讲师／培训内容提供者：已有材料，但把内容做成互动练习耗时，重做场景成本高。是否愿意付费、预算与交付频率尚待访谈。
- 中文演示与英文考试并存：支持中文、英文、中英双语显示，帮助把概念理解与英文术语联系起来；不代表翻译和教学质量已经由官方认证。

**当前用户与付费客户要分开：**玩的人可能是学员，买服务的人可能是讲师或培训负责人。参赛时宜先选一类可接触的客户，不要同时声称服务所有学生、学校和企业。

## 3. 已有产品与实际边界

| 项目 | 当前已有 | 参赛时如何准确描述 |
| --- | --- | --- |
| 游戏形式 | 浏览器2D场景探索、寻物、物件交互、NPC入口 | 可操作的学习游戏原型；不是大型开放世界 |
| 章节 | 四个学习章＋海边、冬季两章独立机关体验 | 章节可独立进入，章内必做任务按顺序推进；后两章不等于另外两门完整课程 |

| 教学流程 | 教学5的基础→示范→引导练习→独立应用；章节交付后正式练习、复习和错题 | 旧教学4／兼容课程仍保留，不能把用户当前旧存档直接说成教学5 |
| 概念小游戏 | 已接23个不同源知识单元、11类玩法，包括规则实验、参数操作、证据判断、分组、样本拟合、数据整理等 | 是限定覆盖，不是139项全部小游戏；任意导入内容也不会自动拥有同等设计 |
| 收藏与掌握 | 新发现的已绑定物件先通过小游戏再收藏；归档移出随身栏；旧收藏可回看体验 | 找到、浏览、收藏、确认基础、应用通过、正式掌握是不同状态 |
| 评价与记录 | 正式章测90%通关、复习／错题、个人成长记录与存档／备份 | 不等于已做教师管理后台、班级学习分析或自动培训报告 |
| 语言 | 中文、英文、双语 | 有显示与流程测试，正式参赛仍需实际试玩核排版与理解成本 |
| 动画 | 本地新加瀑布水纹／落水圈、两处水车转子、原位花草摆动及原有局部环境动态 | 最近一批仅更新本地，尚未上传GitHub；实际观感和性能仍待试玩 |
| 导入与生成 | 多份文字资料导入、可配置兼容Chat Completions的模型接口、生成预览与审核后入库 | 需配置本机服务地址／模型／密钥；PDF扫描件需先提取文字；真实外部模型端到端效果未完成验收 |
| 其他游戏 | 失落的档案馆、星叶群岛、林间寻物社三个独立入口 | 可作为短局设计参考或现有资产，但不要在路演中混淆成同一个玩法 |
| 运行与发布 | Windows一键CMD，本地8782；原四HTML入口保留 | 本地可玩不等于已经有公开可玩的赛事链接或生产级在线服务 |

四个学习章的知识顺序：

1. **AI Fundamentals and Literacy** — AI基础知识和素养。
2. **AI Strategy and Business Value Creation** — AI战略和商业价值创造。
3. **AI Governance and Responsible AI Leadership** — AI治理与负责任的领导力。
4. **Business Readiness, Leadership, and AI Transformation** — 业务准备、领导力和AI转型。

玩家的一段典型体验：进入章节→在场景发现物件→阅读目标与知识→操作对应小游戏并得到反馈→手动收藏／确认基础→进入后续应用→完成章节后正式练习与复习。**这条链很长，不宜作为现场短局的全部演示。**

## 4. AI在哪里，哪些还不是现成功能

已有AI相关能力／证据：

- 材料到知识与课程的模型接口及编译、校验流程；来源、先修、活动与题目的结构化数据。
- AI辅助开发的代码与迭代流程；部分美术有提示词记录，见 `docs/art/world-art-prompts.json`（含people、plants）与 `docs/art/scene-art-prompts.md`。
- 场景、知识物件、教学数据分离，能够复用场景而更换学习内容。

不能据此宣称：

- 每个NPC都是自主运行的AI agent，能演化开放剧情——这是早期灵感方向，不是本轮已验交付。
- 任意资料上传后无需审核就能变成优质小游戏；现有高质量活动有人工设计／审校成分。
- 已证实提高考试通过率、记忆率、留存或收入；目前没有相应用户实验与商业数据。
- 私有课程全文、官方试题、资格认证或官方合作已经取得。

## 5. 与两个赛道的适配：初步判断，待用户决定

| 维度 | OPC｜一个人就是一家公司 | 游戏｜让人想再玩一局 |
| --- | --- | --- |
| 最好讲的价值 | 把客户材料交付成互动学习产品，节省内容制作时间 | 用场景解谜与概念操作带来一局有趣体验 |
| 现有优势 | 已有知识／教学／游戏分层、样例课程、双语和生成接口，可组织成服务流程 | 已有网页游戏、角色／道具美术、寻物、机关、重玩与环境场景 |
| 最大缺口 | 明确买单客户、真实需求证据、样例交付清单、成本／收费依据、对外服务方式 | 短而完整的一局、强主角、直观操作、清楚胜负与重开、再玩动机及主角卡 |
| 演示风险 | 只演示游戏，评委看不出客户为什么付费；或生成演示全是预置内容却说实时生成 | 长课程读卡／刷题压过游戏乐趣，评委无法短时间玩完，主角不突出 |
| 提交补齐 | 能用的产品＋一份具体客户场景的样例交付＋服务谁／怎么收费 | 公开直接可玩链接＋完整短局＋游戏内提示＋主角生成卡 |
| 初步适配 | 更贴近“复用已有材料提供知识服务”的产品主线 | 适合把现有能力切成一个真正好玩的短局，再以学习作为特色 |

**倾向：如果能找到真实讲师／培训内容客户并拿到一小段授权材料，优先考虑OPC。**这只是按产品现状与用户给的条款推导，不是对获奖概率的预测。

如果没有可访问客户、却能迅速做出主角鲜明且让陌生人愿意重玩的3–5分钟短局，游戏赛道也可行。不要为了两边都报而拼成“庞大学习平台＋半个小游戏”，先确认是否允许一作品多赛道。

## 6. OPC路线：最小服务方案（待验证，不是已上线业务）

可先选“有现成AI入门材料的独立讲师／小型培训内容团队”，交付一段互动微课。企业内部培训亦是候选，但客户触达、资料授权与验收链可能更复杂；选择以用户实际能接触的人为准。

建议服务闭环：客户给材料和目标→AI辅助梳理知识／来源→人工审校并选活动→形成浏览器互动样例→客户验收。先卖一段确定范围的交付，不先承诺无限知识库自动化。

一份比赛样例交付可以包括：

- 客户简报：谁、给谁学、原材料是什么、希望解决什么问题。
- 知识地图：一小节的概念、例子、易错点与材料依据。
- 可玩的微课：少量物件、2–3种贴合内容的操作、反馈与重试。
- 交付说明：链接、使用方法、验收条件、人工审校范围。
- 报价说明：包含哪些内容、修改次数、交付时间、哪些需求另计。教师报告若尚无产品能力，可先作为人工交付文件，不能冒充现成自动后台。

收费先讨论“按一个微课／小章节交付”的服务费，而不是未经验证就定订阅价格。用实际制作工时、模型费用、美术／部署成本、审校和修改成本估算，再访谈客户支付意愿。当前没有订单、付费、客单价或盈利数据可引用。

三分钟演示建议：先给出一位客户的具体问题→展示一小段材料如何对应知识与活动→试玩一个有思考的操作→展示最终交付包和报价边界。实时API未成功跑通时，预生成样例应明确标注，不能假装现场生成。

## 7. 游戏路线：最小参赛形态（待设计）

建议将课程大地图收敛为一个3–5分钟的单场景任务，例如“修好知识工坊／完成小镇急件”。这是方向示例，不是现成任务。可选现有动物角色发展为主角，但要给它具体目标、身份和反馈，不能只有NPC菜单。

一局结构：开场一句目标→场景找线索→两种不同的核心操作→结局／成绩→一键重开。重开可用不同线索组合或情境，必须确保真实变化；不要只有题目换顺序。

优先做：

1. 陌生人无需讲解也知道先点哪里，操作提示在游戏内。
2. 能从开始玩到结束，并清楚重开；不强迫先看22个概念。
3. 主角卡完整：一句话／草图、AI生成角色、游戏中实际呈现；已有people提示词只能提供线索，还需选定角色并核对对应原图、生成过程和使用材料。
4. 知识成为玩法：同输入重复运行、实际调参数、找证据等，而不是把答案放在上面要求照抄。
5. 让几位首次接触的人试一局，记录卡点、是否完成、是否自愿重开；不伪造留存指标。

## 8. 参赛前共同缺口

- **规则资格：**已有项目是否可参赛？“两天”是否限定作品创作期？个人／团队要求、报名截止、提交格式、允许复用程度、是否可跨赛道，均待官方确认。应如实区分原有工程与比赛期间新增部分，不能说整个项目两天从零做出。
- **公开链接：**GitHub仓库地址不是试玩链接。当前服务有本机Host限制，不能简单暴露本机端口就称生产部署完成。纯试玩与需要密钥的生成服务应分别设计发布方式，不能把密钥放前端。
- **真实验收：**逻辑／模拟DOM／HTTP通过不等于实际好玩、移动端易用或动画自然；需浏览器、手机及陌生用户试玩。
- **材料与美术证据：**整理提示词、原图到游戏的对应关系和授权／来源记录。来源支持不等于官方题库或课程认证。
- **服务证据：**客户访谈、样例交付、成本记录、反馈目前需补。
- **福利和算力：**用户只贴了标题，没有领取条款；不要推断额度、领取渠道或可用模型。
